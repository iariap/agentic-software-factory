# Lecciones del factory

Registro de las clases de error minadas en las corridas (`/factory-correct`).
Una lección sin **enforcer concreto** no se escribe: cada fila dice qué archivo
la codifica y qué hace, para que el error no vuelva a depender de la memoria
del agente.

`estado`: `codificado` = hay un check determinista que frena la clase de error;
`pendiente` = la fila dice dónde va el fix y por qué todavía no está acá.

| clase de error | lección | enforcer (archivo:qué) | origen (run/PR) | estado |
|---|---|---|---|---|
| Un PR sin rebasar corre los gates VIEJOS (en `pull_request` GitHub usa el workflow del head) y su verde no dice nada del `main` actual | El run de CI que vale es el de una rama que desciende de la base actual: antes de mergear se declara si el head contiene los workflows de hoy; un gate que no se puede probar se declara, nunca se cuenta como verde. | `scripts/gate_base.py` (compara `.github/workflows/**` entre el merge-base REAL y la base que reporta la API —`baseRefOid`—, no el estado del PR ni `--is-ancestor` contra el tip de main, que da falsos negativos con squash-merge; devuelve `fresh`/`stale`/`unknown` con motivo y acción) + `scripts/merge.sh` (`stale` —probado— BLOQUEA; `unknown` —no se pudo probar— AVISA y CONTINÚA, porque bloquear por no poder verificar no compra seguridad y agrega una forma nueva de quedarse trabado) + `scripts/auto-merge.py` (la vía rápida sí es fail-closed en `stale` y `unknown`) + `scripts/babysit.sh` (warn temprano para rebasar antes de esperar el CI). Criterio acotado a `.github/workflows/**` + `.github/actions/**`: es la definición de gates y la señal sin falsos positivos. | x6200 #279 (rama anterior al gate de contraste de #277 ⇒ se mergeó sin correrlo) → `main` rojo en silencio; causa medida y fix en #290; política `unknown` por orden del owner en asf#65 | codificado |
| El atajo local no es el CI: `--quick` deselecciona tests y el rojo aparece recién en el PR | El atajo local no puede deseleccionar nada que un workflow del CI corra; si el modo no se puede interpretar, se declara "no verificable", nunca se asume verde. | `scripts/test_harness.py::quick_shortcut_problems` + `TestLocalShortcutNotCI` (parsea el bloque `--quick` de la suite local de cada app, mapea cada suite omitida a su runner y falla si un workflow del CI lo corre; el caso real x6200 pasa porque `--quick` omite `js8` y el CI no lo corre) | app (suite local `tests/run_all_tests.sh --quick`: 22 OK) vs pytest del CI: falló un test deseleccionado (`tests/test_natural.py`) en el PR #285 | codificado |
| Un número medido en TRES lugares (constante del test + artefacto de evidencia comprometido + pins del pytest): actualizar uno deja los otros viejos y el gate miente | Un valor medido tiene UNA fuente: los demás lo leen o lo regeneran con un comando, nunca lo copian; y el comando de re-baseline imprime cada cambio (viejo → nuevo) para que sea revisable. | regla acá + propuesta en el repo de la app: el test importa el valor del artefacto versionado (o un generador lo escribe en los tres lugares) y el re-baseline imprime `~ viejo -> nuevo` (patrón ya implementado en el `--update-baseline` de x6200 #290). El harness no puede detectar el desalineamiento sin un adaptador por app: el formato de las tres fuentes vive en el repo de la app. | app: valor esperado de `tests/test_natural.py` en constante + artefacto comprometido + pins del pytest | pendiente: el fix es en la app (una fuente o un generador); el harness no tiene ese formato |
| Un gate sin control negativo se declara bueno sin haberlo visto fallar: falso verde y agujero que sólo aparecen al inyectar la regresión | Ningún gate se declara bueno sin verlo fallar: cada gate de la cadena de merge tiene un control negativo registrado, y si el control desaparece o el gate se borra, el CI se pone rojo. | `scripts/test_harness.py::TestGateNegativeControls` (registro gate → test que lo hace fallar; verifica que el archivo del gate y el test existan) + los controles negativos reales: `TestBaseGateMergeChain.test_stale_base_blocks_the_merge`, `TestMergeGuard.test_dirty_rejected`, `TestMergeWhenGreen.test_class_c_writes_evidence_and_exits_5` | x6200 gate de contraste (#277): falso verde por reusar un binario viejo + agujero "tinta del color del fondo ⇒ no había píxeles y se clasificaba sin tinta"; los dos aparecieron sólo al probar el rojo (#290) | codificado |
| El nombre del job no es el veredicto, y un check que no corre (o corre sobre otro sha) miente | Se lee el step fallido y el artefacto (`visual.json`), no el nombre del job; sin checks o con un run de otro sha, se declara: no es un gate verde. | `scripts/ci-status.sh` (por run fallido imprime los steps fallidos de cada job, el extracto del log con firma de fallo y los artefactos con su JSON — baja los chicos para mostrar el veredicto medido; declara "el PR no tiene checks" y "el run corrió sobre otro sha") | x6200 job `UI Visual Regression` (falla por el gate de contraste o por Performance; el veredicto está en `visual.json`) + #289 (CI opt-in: sin la etiqueta los gates no corren) | codificado |
| Inventario versionado desactualizado (fixtures, waivers, roles de tema) ⇒ rojo sólo en el CI | El inventario versionado se valida con el mismo comando que el CI, y el trigger local no puede depender de que el diff toque `.py`: un fixture `.scn`, un golden o un `quality/*.yaml` también lo desactualizan. | `scripts/apps/x6200/check-matrix.sh`: el pytest del arnés A/B corre con **cualquier** cambio en `tools/ab_testing/**` (antes sólo con `*.py`), y la matriz corre `x6200-ab themes` + `x6200-ab contracts` con el trigger y el comando del workflow `ab-testing.yml` (antes no los corría: el rojo de contratos sólo aparecía en el CI). | run 39360558700 (PR #171: rol `hex_5a2ca0` en `src/theme.h` sin definir en los 10 temas), run 39466919720 (PR #179: inventario de fixtures + lista de waivers), run 39500020197 (PR #183: job `UI Quality Contracts`) | codificado |
| Divergencia local↔CI por el submódulo `lvgl/` | Un gate que compila C tiene que compilar en local por el mismo camino que el CI: si el local usa el submódulo pineado y el CI otra copia (u otros stubs), el verde local no dice nada del CI. | `tests/native/run_native_tests.sh` del repo de la app (`iariap/x6200_gui`): paridad de stubs del submódulo — PR aparte en ese repo, no en el harness. | run 39516311133 (PR #187) | pendiente: el fix vive en el repo de la app; el harness no puede codificarlo con un archivo propio |
